# Roadmap

Measure accepted user outcomes, not registry size or tool counts.

## 1. Correctness and release foundation

- Preserve the F1–F6 regression cases and extend acceptance beyond the bounded local repairs.
- Keep every release tied to a reviewed commit, CI results, source/data attribution and clean wheel installation.
- Add typed output contracts and migrations as the model stabilizes.
- Preserve original inputs and explicit uncertainty; never silently relax a requested condition.

## 2. Evaluate existing engines

The local 0.2.6.dev1 milestone selected pinned direct pydna for a bounded two-fragment circular homology operation after a five-fixture comparison with DNA Cauldron. The local 0.2.7.dev1 milestone adds [explicit fragment planning](reference/fragment-planning.md) and synthetic objective-to-artifact replay. See the [assembly contract](reference/homology-assembly.md). This does not select a universal backend or finish the broader method evaluation below.

Compare a pinned subset of [OpenCloning/pydna](https://github.com/OpenCloning/OpenCloning_backend) with direct [pydna](https://github.com/pydna-group/pydna), and [DNA Cauldron](https://github.com/Edinburgh-Genome-Foundry/DnaCauldron) where the selected assembly family warrants it. Use identical fixtures and one authoritative backend per operation. Check independent sequence/annotation expectations, ambiguity, history, dependency compatibility and rights.

[DNA Chisel](https://github.com/Edinburgh-Genome-Foundry/DnaChisel) is a candidate for explicit constraints/optimization. [pLannotate](https://github.com/barricklab/pLannotate) is an optional inferred-annotation candidate; it must not overwrite authoritative source annotations. Compare the small current renderer with [SeqViz](https://github.com/Lattice-Automation/seqviz) and [CGView.js](https://github.com/sciguy/cgview-js) on offline geometry/accessibility fixtures before adding custom viewer features.

[Biomni](https://github.com/snap-stanford/Biomni) is a candidate agent integration host. [ScienceIDE](https://github.com/aitofound/ScienceIDE) motivates independent outcome verifiers; [AI-Build-AI](https://github.com/aibuildai-inc/AI-Build-AI) motivates explicit candidate budgets and comparison. These are references, not installed dependencies or validated VGET capabilities.

## 3. One complete reviewed workflow

Choose one exact host/context, one reviewed convention and a bounded permitted parts collection. Demonstrate both create and modify from ordinary-language objectives, plus consequential ambiguity and unsupported cases. The calling agent must discover and justify inputs; users should not have to select and order every part manually. Check both output artifacts independently.

Test through two agent integrations and compare against manual work and a general agent with scientific tools. Record acceptance, repair time, correct clarification/unsupported outcomes, elapsed time and cost. Freeze held-out fixtures before tuning. Reviewers and representative objectives must be selected before claiming product fit.

## 4. Expand scoped coverage

Preserve all nine host targets and promote each only with its own reviewed evidence. Add public parts according to missing roles in evaluated workflows. Continue iGEM/NCBI acquisition; Addgene API integration is optional until approved access exists. No private or restricted dataset becomes public merely because a connector can retrieve it.
